# 文章逻辑审校（report-logic-audit）

交付前用。它不判你的观点对不对，只判三件事：**话有没有说通、证据够不够、推理有没有收到落点。**

适用于任何已完成的中文文章：研报与行业报告、评论时评、学术论文与综述、科普、方案与可行性、汇报公文、白皮书、讲稿、教程 SOP。

---

## 它解决什么问题

文章写完自己读三遍，看不出问题——因为你在读"自己想说的"，不是"纸上写的"。常见到交付才被发现的有：

- 主张写了，证据是隔壁那段的一个数字，中间没人搭桥
- 前半篇说 A 行业，后半篇口径换成 B，数据都对，全篇打架
- 结论是"必然""确定"，没有任何成立条件，事后无法验证对错
- 改稿改到第 12 处，前面第 3 处的数字忘了跟着改
- 润色完读着很顺，但主张被悄悄改硬了，没人回头核

这些都不是错别字，是**链条断了**。本技能把链条拆成六段，逐段查。

## 六关查什么

| 关 | 查什么 | 典型病灶 |
|---|---|---|
| 一 · 论点—证据闭环 | 每个主张有没有证据，证据强度是否匹配主张强度 | 有主张无证据、孤证、证据与主张不同量级 |
| 二 · 概念与口径一致 | 术语是否漂移、同一指标是否换了口径 | 同义异名、含税/不含税混用、同比与累计混用 |
| 三 · 结构完整与衔接 | 章节是否残缺、图表是否都有解读、体裁要素是否齐 | 缺章跳号、悬空引用、有图无解读、必写要素缺失 |
| 四 · 逻辑链条 | 推理每一步是否成立 | 相关当因果、中间环节缺失、归因单一、定义偷换 |
| 五 · 推理终结 | 推理是否停在"讲了道理"而没到"能被验证" | 无机制、无条件边界、无反例处理、无可证伪判据 |
| 六 · 数据与图文一致 | 跨处数字是否自洽、图内单位是否与正文同口径 | 同一数字两处不一、轴写 % 标签写倍、图表编号重复 |

**第五关是本技能的核心。** 它只问一句：这条结论，什么情况下算错？答不上来，就是"未终结"。每条主结论都要进一张**证伪台账**：

| 结论 | 怎么算错 | 看什么、什么时候 |
|---|---|---|
| 下半年毛利率回到 30% | Q3 毛利率仍低于 27%，或回升靠一次性收益 | Q3 季报毛利率、非经常性损益占比 |

写不出判据的结论，要么降级为"待观察"，要么删掉。

## 三个环节，两个模式（外加格式审校）

```
① 论证骨架  →  ② 六关审校  →  ③ 润色
  （读懂）      （判、定位）     （改表达层）
```

**顺序不可颠倒。** 边读边改，改到最后会忘掉原始问题出在第几段；更麻烦的是句子顺了以后，证据不足和推理跳跃反而被"顺"过去——读者读着舒服，问题还在。所以润色是独立模式，默认只出建议、不改文件。

**格式审校（模式三）独立于这条链**：字体字号行距、标题层级、错别字、全半角——跟逻辑无关，但定稿前要过。单独跑 `check_format.py`，不要混进审校或润色。

骨架这一步还有个实际作用：**每条发现都要能挂到骨架的某个节点上，挂不上的先怀疑是误报。** 这是去噪机制。

## 环境

- **Python 3.8+**。除 `.docx` 外只用标准库，无第三方依赖。
- 读 `.docx` 需要 `python-docx`：`pip install python-docx`。读 `.md / .txt / .html` 零依赖。
- 无网络请求、无外部 API、不读技能目录以外的文件。`--apply` 只写你指定的输出文件。

## 快速开始（30 秒看效果）

仓库里带了一份**故意写坏**的样例，装完先跑它：

```bash
cd ~/.workbuddy/skills/report-logic-audit

# ① 先搭骨架
python scripts/summarize_outline.py examples/sample-bad-article.md --genre essay

# ② 过六关
python scripts/audit_docx.py examples/sample-bad-article.md --genre essay

# ③ 推理有没有落点
python scripts/check_reasoning.py examples/sample-bad-article.md

# ④ 润色（默认只出建议）
python scripts/polish_docx.py examples/sample-bad-article.md
```

`python` 不存在时用 `python3`（macOS / Linux 常见）。

### ① 骨架

```
体裁：essay｜正文 587 字｜章 5｜图 0｜表 0｜断言 4

| 章 | 标题 | 字数 | 占比 | 断言 | 断言/千字 |
| 1 | 问题的由来 | 50 | 8.5% | 0 | 0.0 |
| 3 | 效率确实下降了 | 122 | 20.8% | 2 | 16.4 |
| 5 | 影响 | 60 | 10.2% | 1 | 16.7 |
| 6 | 结语 | 129 | 22.0% | 1 | 7.8 |

**编号异常**：缺第 2 章 —— 批量改稿「假成功」最常见症状
**结论倾倒区**：「影响」断言密度 16.7/千字、篇幅仅 10.2%
```

两个信号值得记：
- **编号异常**：跳号/重号，通常意味着有整节没合进来，或改稿改丢了
- **结论倾倒区**：断言密度 ≥8/千字但篇幅 ≤12% 的章，判断堆在最短的章里，多半只有宣言没有论证

### ② 六关

```
[BLOCK] CH-GAP      @ 三、效率确实下降了 :: 章节缺号：缺第 [2] 章
[BLOCK] PH-RESIDUE  @ …具体影响程度 TODO 后续补充 :: 占位符残留：TODO
[BLOCK] MUST-MISS   @ 全文 :: 必写内容缺失：反方（或 对立观点/反驳/批驳）
[FIX]   X2-GROWTH-BEI @ 即增长了 1.5 倍 :: 「增长 1.5 倍」表述歧义（增长1倍=变2倍）
[FIX]   E-ABSOLUTE  @ 这充分说明…必然降低效率 :: 绝对化用词且同句无任何依据
[FIX]   FIG-REF-MISS @ 正文提到图3 :: 引用图3，但全文无「图3：」编号对象

汇总: BLOCK=4 FIX=4 SUGGEST=0
```

`BLOCK` 必须清零才能交；`FIX` 逐条判断；`SUGGEST` 挑着看。

### ③ 推理终结

```
结论性断言 3 条（已终结 0 / 半终结 1 / 未终结 2）

1. [未终结][三、效率确实下降了] 这充分说明远程办公必然降低效率，这一点毋庸置疑
   缺：机制/条件/反例/判据
2. [半终结][五、影响] 远程办公降低了效率，所以企业应当取消远程办公
   缺：条件/反例/判据
```

### ④ 润色

```
建议 8 条｜可自动落地 2 条｜需人工确认 3 条

🟡 [P-REDUND] 第8块｜「事实上」→（删）
     理由：删除会改变口吻，语气是作者的
🔵 [P-ALIAS]  全文｜「远程办公×8 / RWA×2」
     理由：文中已声明简称，正文却全称与简称混用
🔵 [P-REDUND] 第10块｜「由于…的原因」→「由于…」
```

### ⑤ 格式审校（模式三）

排版定稿用，与逻辑无关但交付前同样要过：错别字与易混词、全角/半角字符、标题层级（跳级、正文误用标题样式）、中文字体混用、字号、行距、中英文空格与数字单位写法。

```
🟡 须修 8｜建议 3｜格式问题不阻断交付

  F-TYPO｜第2行
    「帐号」应为「账号」（…截至发稿，帐号体系运行正常…）
    → 改为「账号」
  F-HEAD｜标题「细分行业」
    标题跳级：上一级 H1，这里直接 H3
    → 插入中间层级或把本标题升一级
  F-FONT｜正文中文字体
    混用：多数「宋体」之外还有 微软雅黑×1
    → 统一为「宋体」（--fix 可自动落地）
```

`--fix`（docx 专属）只统一中文字体与正文行距（落在占多数的值上），**落地前后逐段比对文字，多一个字符就整份放弃**；错别字、全角字符、标题层级、字号永不自动改。

## 参数速查

```bash
# 骨架
summarize_outline.py 文章.docx [--genre essay] [--top 5] [--md 骨架.md]

# 审校
audit_docx.py 文章.docx [--genre {essay,research,academic,explainer,plan,\
report-gov,copy,speech,howto,general}] [--must-have "反方/对立观点"] [--claim-table]

# 推理终结（--strict 把"未终结"升为阻断）
check_reasoning.py 文章.docx [--strict] [--top 10]

# 润色（默认只看建议；--apply 写新文件）
polish_docx.py 文章.docx [--apply] [--out 结果.docx] [--inplace] \
    [--term-group "锂电设备/锂电装备"] [--long-limit 45]

# 格式审校（默认只出清单；--fix 统一字体行距，docx 专属，文字逐字校验不变）
check_format.py 文章.docx [--fix] [--out 结果.docx]
check_format.py 文章.md          # md/txt 只做文字层（错别字/全角/空格规范）

# 图内单位（读绘图脚本的常量，不看像素）
check_fig_units.py --figs data --docx 报告.docx [--json 图检.json]
```

`--genre` 决定按哪种体裁的规矩判（必写要素、结论位置等）。不填按 `general` 处理；传 `--industry` 会自动按 `research` 处理。九种体裁各自的必写要素与高频病灶，见 `references/genre-packs.md`。

### 退出码（接 CI 时会用到）

| 脚本 | 退出码 |
|---|---|
| `audit_docx.py` | **有 `BLOCK` 时返回 1**，无 `BLOCK` 返回 0——可直接当交付门禁用 |
| `check_reasoning.py` | 恒返回 0（`--strict` 只改分级，不改退出码） |
| `check_format.py` | 恒返回 0（格式问题不阻断交付）；`--fix` 文字校验失败时返回 1（已删除输出） |
| 其他两个 | 正常返回 0 |

所以 `audit_docx.py` 报出一堆 BLOCK 后退出码是 1，是设计如此，不是崩溃。想串进流水线：

```bash
python scripts/audit_docx.py 新稿.docx || { echo "有阻断项，不许发布"; exit 1; }
```

## 润色的四条硬约束

写进脚本了，不是口头约定：

| 约束 | 为什么 |
|---|---|
| 数字一个不动（逐段比对数字序列，变了整段回滚） | 润色悄悄改掉一个数，比任何逻辑错误都致命 |
| 删除类永不自动 | 删"事实上""总体而言"会改作者口吻，语气是作者的 |
| 论证段只报告 | 含"因此/说明/机制"的段落，改一个词可能就把因果方向改了 |
| 落地后自动重跑审校，BLOCK+FIX 不得增加 | 防止"越润越糟"，这是唯一能自证的验收 |

## 不适用

- **不判观点对错**。观点是否成立、预测是否准确，本技能不负责。
- **不替代事实核查**。数字真假要靠取证（年报、公告、权威信源）。
- **读不了图里的字**。图内文字是像素，除非绘图脚本按约定写成可解析的常量。
- **扫描件 / 图片型 PDF** 读不到文字，先 OCR。
- **不做改写重组**。段落结构、论证顺序动不了——那是重写，不是审校。

## 已知边界（别把它当金标准）

- 脚本的 `SUGGEST` 有误报，`FIX` 也可能误判——**脚本给位置，人给结论**。
- 术语统一不自动猜：无分词库时硬猜同义词只会产出噪声（实测在一份 1.5 万字研报上产出 99 条残片）。术语用 `--term-group` 自己给。
- 骨架里的"论证路径"是按标题关键词猜的，标题含糊时只能给"并列（弱信号）"，此时以人读为准。
- `polish_docx.py --apply` 只在单 run 内替换。Word 里改过格式的句子会被切成多个 run，这类位置只报告不改。
- 长句判据是"连续 45 字无任何标点"，不是"整句字数超限"——用「、」分层的长枚举句读起来是清楚的，不该报。
