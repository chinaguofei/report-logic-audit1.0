## ⭐ 数据源分层约定（v1.2.0，2026-11-04 定案；补做前讨论结论落地）

**结论先行：不整体替换主源。** 研报数据的瓶颈从来不是行情/财务接口，而是 v1.1.6–1.1.8 新增的 **D 类非结构化年报正文数据**。A/B/C 类现有东财 + 腾讯已覆盖，再引入商业数据源属重复建设。

| 数据域 | 内容 | 通道 | 状态 |
|---|---|---|---|
| **A** | 结构化财务 / 股本 / 资产负债表 / 利润表 | **东财 datacenter 首选**（`RPT_F10_FINANCE_MAINFINADATA` / `GBALANCE` / `GINCOME` / `RPT_DMSK_FN_BALANCE` / 股东户数 / 十大流通股东） | 主源，不动 |
| **B** | 行情 / K 线（**估值通道单列，见下节**） | **腾讯 `qt.gtimg.cn` + `web.ifzq.gtimg.cn fqkline`** | 行情主源，不动 |
| **C** | 股东筹码 / 机构席位 | 东财 datacenter | 主源，不动 |
| **D** | **产能基地 / 三量两率 / 存货结构 / 单价与单位经济 / 在建转固** | **年报 PDF + 上交所/巨潮公告摘录 + 半年报「主要财务数据公告」** | **新增必需通道** |
| **E** | 定性判断 / 外部研报共识 | WebSearch（只给方向，不进数值） | 参照 |

> **口径纪律（重要）**：上表 A–E 是**数据域**（工程取数分层，回答「去哪取」），与报告附录「数据来源与分级说明」的 A–D **来源等级**（合规水印，回答「可信度多高」）是**两套正交维度，不得混用**。年报/公告里的产能、存货结构属「数据域 D + 来源等级 A」；据此自算的周转天数、量价拆分属「数据域 D + 来源等级 D」。报告附录仍按来源等级 A/B/C/D 标注，不改写。

**三项定案（2026-11-04）**

1. **A/B/C 类不引入理杏仁**（财务主表 / 行情 K 线 / 股东筹码）。Open API 覆盖这些域，但与现有首选源重叠；需额外 token 与限流治理，不解决 D 类缺口。**例外：估值通道首选理杏仁（2026-11-04 23:16 用户定案），见下节**。
2. **D 类允许且必须使用年报 PDF / 交易所公告摘录**。这是产能七要素唯一可得通道。每条 D 类数值必须带：来源文件名 / 披露日 / 口径说明；反推值须标注「反推，仅作量级参考」。
3. **WIND 不进自动化主链路**。`WindPy` 依赖本地 Wind 终端进程、交互式授权会话与提取量限制，无法无人值守。仅在用户确认有终端授权时作**人工核验位**（核一致预期与关键产能数），不写进抓取脚本。

**D 类取数铁律（违反即视为编造）**

### 估值通道子域：理杏仁为首选源（2026-11-04 23:16 用户定案；23:10 初判修正）

**修正说明**：22:30 版把「理杏仁不引入」一刀切覆盖全部数据域，判断偏粗；23:10 改为「可选增强、默认关闭」仍偏保守；23:16 用户定案**升级为首选源**。

**用户定案理由**：理杏仁对公司行动（送转 / 除权 / 股本变动 / 财报披露日切换）已做内建对齐，其他源未必处理到位。此判断成立——自建 `draw_valuation*.py` 用 `SPS = 营收TTM / 最新总股本` 回溯全窗口，叠加手工 `NOTICE_DATE` 阶梯与 `SPLITS` 送转登记，是整条链路最易产生口径误差的一环；理杏仁按日直接返回 `ps_ttm` 及分位统计，恰好替掉这层拼接。

| 项 | 说明 |
|---|---|
| 接口 | `POST https://open.lixinger.com/api/cn/company/fundamental/non_financial`（A 股非金融；创新药适配） |
| 指标 | `ps_ttm` 日序列；`ps_ttm.{fs\|y20\|y10\|y5\|y3\|y1}.cvpos / q2v / q5v / q8v`（分位点与 20/50/80 分位对应值）；另有 `pe_ttm` `pb` `mc` |
| 约束 | 需用户私有 token（实名创建）+ 基本面 API 套餐；`startDate` 单只票、区间 ≤10 年；限流 1000 次/分、32 次/秒 |
| 状态 | **首选源，允许降级**（2026-11-04 23:16 由「可选增强、默认关闭」升级）。降级触发条件与强制标注见下方铁律 5 |

**启用铁律（防两套数混进报告）**

1. 只新增独立文件 `data/valuation_lixinger_{code}.json`，**禁止回写** `matrix_data.json` / `val_bps_*.json` / `val_k_*.json`。
2. 绘图脚本用 `VAL_SOURCE = "lixinger" | "eastmoney"` 显式开关，**默认 `lixinger`**。切换时 MUST 同步更新正文第八章 PS 现值与分位、三情景图 `CHANNEL`、指标切换页 —— **禁止只换图不换文**。
3. **双源交叉验证**：接入理杏仁后仍计算一次自建 PS；两源当日 `ps_ttm` 相对差异 > 5% 时**以理杏仁为准**，但 MUST 在报告附录披露差异值与自建口径结果，不得静默替换。
4. token 只存本地环境变量，禁止写入技能包 / 报告 / 日志 / 云端 zip。
5. **降级规则（防首选源不可用时卡死或静默换源）**：触发条件 = 未配置 `LIXINGER_TOKEN` / 401 鉴权失败 / 429 持续限流 / 返回空数组 / 数据起始晚于所需窗口。触发后自动降级到东财 F10 + 腾讯**不复权**日 K 自建通道，并 MUST 在报告附录「数据来源与分级说明」写明「本次估值通道采用备源（东财 F10 + 腾讯不复权日 K），原因：XXX；理杏仁为首选源，未取用」，同时记入 `meta.source`。**禁止静默降级、禁止降级后仍引用理杏仁分位数、禁止两源数值混用**。

**价格口径纪律（2026-11-04 23:16 补、23:27 勘误）**

- 原写「估值通道**必须用不复权价**、前复权价会失真」是**错误的绝对化表述**，已由「估值通道」节的「⭐ 价格与每股值口径配对硬规则」取代并实算验证：**前复权价在配对最新股本口径每股指标时同样正确，且序列更连续**（用户 23:16 判断成立）。
- 理杏仁 `ps_ttm = 总市值 / 营收TTM` **本身即市值口径**，已内含公司行动与股本事件对齐；取用后**直接画通道，不得再乘价格、不得再做任何复权处理**。用户所说「前复权处理」在理杏仁这里体现为**公司行动与股本事件对齐**，不是价格序列复权。
- K 线技术分析图固定用前复权；估值通道按配对规则选 A/B/C，`draw_kline.py` 与 `draw_valuation*.py` 的价格序列必须分别读取。

- 产量 / 销量 / 产能利用率 / 产销率 / 单价 / 单位成本 / 单位毛利 / 存货结构未披露 → **明写「未披露，无法量化」**，禁止用毛利率、营收增速或行业均值倒推后当作公司数据。
- 单价不可得 → 按 v1.1.8 降级为「毛利率变动 pct + 营收增速」双判，**禁止据毛利率上升宣称单价上涨**。
- 不同量纲产能（粒/年 vs 升 vs 平方米）**不得合并成单一总产能**；须声明采用「厂区口径」还是「城市口径」，CMO 单列不计入自有基地数。
- 库存与产销率冲突时，**以存货余额（审计时点数）与存货周转天数为准**；存货上升且周转变慢不得写「在去库存」。
- 全部 D 类数据落 `data/d_class_{code}.json` 单源，含 `meta.layer` / `meta.source_urls` / `not_disclosed` / `downgrade` 四个必填键。

```text
A 资产负债表  RPT_F10_FINANCE_GBALANCE  → INVENTORY / CIP / CONTRACT_LIAB / FIXED_ASSET
A 利润表      RPT_F10_FINANCE_GINCOME   → TOTAL_OPERATE_INCOME / OPERATE_COST
```

## 估值通道（第九章第 4 节，2026-09-27 新增；2026-10-17 增加 PS/PB 分派）

### 估值指标选择（2026-10-17 用户定稿，硬规则）

**高成长科技公司用 PS（市销率），传统公司用 PB（市净率）。** 按下列顺序判定，命中即用：

| 顺序 | 判定条件 | 采用 |
|---|---|---|
| 1 | **亏损 且 属科技成长类**（最近完整年度归母或扣非 ≤ 0 → PE 失效，但收入规模仍是有效定价锚） | **PS 强制** |

**强制要求**

3. **前复权价可以进估值通道**（路径 B），但仅在与最新股本口径每股指标配对时成立；第八章 K 线技术分析图固定用前复权，两张图的价格序列必须分别读取。
4. 降级到自建时：沿用当前脚本走路径 A；若改走路径 B，MUST 先跑 `RPT_SHAREBONUS_DET` 核实送转事件、清空 `SPLITS` 的每股值还原逻辑，并用上述四路径实算自检。

要点：
- `BPS` = 每股净资产（元）；`NOTICE_DATE` = 披露日，通道线在披露日后切换到新一期每股值（阶梯跳变来源）
- **PB(t)** = 价格 / 当期 BPS；**PS(t)** = 价格 / 当期 SPS。价格用不复权还是前复权，**由上表配对规则决定**，不是固定值
- `SPS = 营收 TTM / 总股本`；**营收 TTM = 上年全年 + 本期累计 − 上年同期累计**（报告期为 12/31 时直接取全年）。亏损公司 PS 依然有效，这正是高成长科技用 PS 的原因
- 通道线 = 窗口内日指标的 0/20/40/60/80 分位倍数 × 当期每股值（股价尺度）
- 绘图脚本 `scripts/draw_valuation.py`（改 **5** 个常量，含 `METRIC = "PB" | "PS"`）；正文引用极值/分位前必须用脚本尾部核实输出，禁止估算
- **同一披露日挂了多期**：东财对上市前历史数据常统一填招股书披露日（如 2024-07-12 同时挂 2024Q1/2023 年报/2023Q1）。脚本按**报表期最晚的一期**取；不要按文件行序覆盖（否则会取到更老的报告期，PB 偏高）
- **送转坑（2026-10-17 301608 实战）**：公司实施送转（如「10 转 4.9」，1 股→1.49 股）时，除权日不复权股价跳空下跌约 33%，而 F10 的 BPS 仍是除权前股本口径，PB 会出现假断崖。在 `SPLITS` 里登记 `(除权日, 因子)`（10 转 4.9 → 1.49），脚本自动折算。**两个指标方向相反**：PB 的 BPS 是"报告期股本口径"→ 除权日前的 BPS **÷F**；PS 的 `TOTAL_SHARE` 实测恒为"最新股本"→ 除权日前的 SPS **×F**（脚本用 `SHARE_IS_LATEST` 自动判别，勿手改）。送转数据用 `reportName=RPT_SHAREBONUS_DET&columns=ALL&filter=(SECUCODE=301608.SZ)` 查 `IT_RATIO`（送转比）、`EX_DIVIDEND_DATE`（除权日）、`PRETAX_BONUS_RMB`（派现）。
- **⚠️ 送转的反向陷阱：BPS 可能已按最新股本回溯折算 → `SPLITS` 应为空（2026-10-17 300072 实测）**。东财 F10 有时会把**历史全部期次的 BPS 统一按最新股本重算**，此时序列里已内含送转，再按除权日 ÷F 就是二次折算，会在除权日凭空造出假台阶。
  - **判别方法（必须实测，不能靠猜）**：取送转前一期，用 `BPS × 最新总股本` 反推权益，再与当期报表归母净资产比对。若 ≈ 权益 → 已按最新股本折算 → `SPLITS = []`；若 ≈ 权益 × F → 仍是旧股本口径 → 需登记 `SPLITS`。
  - 300072 实证：2025 中报 BPS 2.5282 × 23.497 亿股 = 59.41 亿元 = 当期权益 → 已折算；若按除权前 15.77 亿股应为 3.7671 元。故 `SPLITS=[]`，否则 05-20 处会造出 PB 2.72（真实 1.83）。
- **⚠️ 窗口起点事件校正（2026-10-17 300072 实测）**：`pageSize=24` 会混入报告期在五年窗口之外的旧期次。若不剔除，窗口起点前的几个交易日会退回到最早那条旧事件的每股值，画出一段与窗口内首期不连接的假台阶。脚本已自动处理：若窗口起点之前没有任何披露事件，则用"窗口起点前最后一条"作初始值（但仍需肉眼复核图左端是否平整）。
- **⚠️ 小数位**：通道倍数打印必须保留 2 位（`%.2f`）。用 `%.0f` 会让不同分位数显示成同一个数字（如 0.60/0.58 都印成"1x"），正文引用时极易出错。
