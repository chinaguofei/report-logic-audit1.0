## 九条硬规则（每条都曾出过事故，交付前逐条过）

1. **口径纪律**：全文只能有一个"所处行业"；其余只能作"工艺邻接/对照口径"。主口径的表/图必须排在邻接口径之前。
2. **单位纪律**：增速一律 `%`，禁止"倍/翻倍"；"倍"只用于估值倍数与规模关系；同组标签单位必须唯一（生成脚本内 `_assert_units()` 前置断言 + 交付前 `check_fig_units.py`）。
3. **章序纪律**：一章一主题；**并题优先于拆章**（标题与内容不符→改标题，不新增章节）；小结＝结论章，必须在估值之后；**风险提示＝正文末章**（其后只允许数据来源/免责声明）。
4. **图表化优先**：能用图表达的不写长段（六维打分、订单、产业链、利润构成、季节性、三情景）；每张图后必须紧跟一句结论。
5. **季节性论证**（第八章③必写）：收入侧实证 + 股价侧统计（含显著性说明）+ 翻译成验证时间轴与可证伪判据，不得用季节性直接推股价。
6. **数据分级**：A 法定披露 / B 第三方机构与主流媒体 / C 券商研报与一致预期（仅参照）/ D 本报告自算（标假设）；每个关键数字都要能落到某一级。
7. **数据单源三原则（P05，2026-10-29 用户定稿，强制；同日经迅捷兴治理审计补 4 子项）**：
   - **单源引用**：全部数据数组（单季矩阵、同比、户数等）只存在于唯一数据文件（`data/matrix_data.json`，由 compute 脚本产出并带 meta 溯源）；绘图、矩阵页、正文脚本一律运行时读出，**禁止在任何脚本里硬编码数值副本**。
   - **一次读出**：每个脚本只 load 数据文件一次；累计口径（前三季/H1/年度）由单季数组现算派生，不手填。
   - **录编前校验**：build 脚本第一步强制跑 data_check（单季回加=年报累计、同比重算、逐行无缺格、A 级锚点），不过即终止出报告。
   - **披露值优先（meta.anchors）**：累计同比、BPS 等有官方披露口径的数字，显示值一律用披露值（存 `meta.anchors`，带字段溯源）；单季求和派生值仅作内部校验，不进正文——防「派生 +97.33% 冒充披露 +97.29%」。
   - **时效性锚点核对（公告日晚于/等于报告日）**：报告期内若有新公告（季报/年报）披露日 ≥ 报告日，BPS/PB(LF)/TTM/股本四类锚点必须重拉重算——机械关对此类过时无感知（实战案例：PB 9.95→9.07×，情景区间级联下移）。
   - **终稿独立对账**：出件前用独立接口重算 16 季单季逐格对账（容差 0.005 亿）+ 行情快照核对；补丁落盘必跑 `py_compile`。
   - **派生数禁入图脚本**：图脚本（draw_*）配置区同样禁止硬编码派生值（累计、占比、现价、BPS、募资额等）——一律从矩阵/meta 派生（迅捷兴曾因此出现 0.7620 vs 0.7619 漂移）；行情/股本快照统一存 `meta.mkt` 块（含来源与日期），跨文件数据（如 val_*.json 末位 BPS）须与 meta 做一致性断言。
   - **克隆残留关**：克隆旧报告模板后，出图前先对**图脚本源文件**跑禁词 grep（旧公司简称/代码/领域词），成品再跑 `report-logic-audit` 的 `check_residue.py --ban` 关卡（v1.1.4+）——迅捷兴图 3 曾残留北芯「IVUS」子图标题，渲染出图文矛盾的图。
   - **路径锚定**：data_check 等校验脚本以自身位置锚定项目根（`os.chdir(dirname(abspath(__file__))+'/..')`），任何目录运行结果一致；矩阵单季存 6 位小数，避免求和与累计锚点出现尾差。
8. **产能与库存必写且必互验（v1.1.6 立产能量，v1.1.7 加库存验证）**：第一章必写小节「生产基地布局与投产进度」七要素缺一不可——基地清单 / 三量两率 / **库存变动** / **价格与单位经济** / 新增产能来源（自建·并购·租赁）/ 在建与转固 / 利好利空判定。**产销率与存货余额方向冲突时，以存货余额（审计口径）与存货周转天数为准**，存货上升而产销率 >100% 禁止写"在去库存"，须解释口径差（外购转售 / 发出商品 / 提前备货）。库存必取定期报告资产负债表，**不得由产销率倒推**。
9. **量价必拆（v1.1.8）**：只写"量增"或只写"毛利率下降"都不算完整。必须同时给**单价**（元/片、元/件；无分产品收入则用混合单价并标注"含非模组收入、仅作量级参考"）、**单位成本**、**单位毛利（元/件）**、**毛利率变动 pct**，然后落量价四态（量增价升=利好 / 量增价跌=以价换量 / 量跌价升=收缩保价 / 量跌价跌=利空）。**毛利率是比率、会被成本基数稀释；单位毛利额是绝对值**——二者反向时必须同时写出并解释（隆利 300752：单位毛利额 +28.8%、毛利率 −1.04pct = 结构改善但成本管控未跟上），**不得二选一**。单价算不出就写"单价未披露，无法量化"，**禁止**用毛利率代替单价却说"单价上涨"。

## 工作流（严格按序执行）

### Step 1 · 确认标的与市场

1. 从用户输入取股票代码或名称，判定 A 股 / 港股。
2. 代码前缀规则：`sz`(0/3 开头)、`sh`(6 开头)、`hk`(港股)。
3. eastmoney SECUCODE 格式：`002536.SZ` / `600685.SH` / `03696.HK`（**后缀大写、无前缀**）。
4. 不确定时用行情接口验证名称：
   ```bash
   curl -s "https://qt.gtimg.cn/q=sz002536" | iconv -f gbk -t utf-8
   # 港股：q=hk03696；返回 v_pv_none_match="1" 说明代码不存在
   ```

全部取数细节见 `references/data-sources.md`（接口 URL、字段名、翻页要求、坑位）。必抓清单：

### Step 3D · 第四章「财务质量甄别」小节（2026-09-27 用户确认常设）

第四章解读段之后**固定追加**「财务质量甄别」小节——把第四章从"展示数字"升级为"判断数字质量"。执行方式：**调用 `fraud-detector` 技能**（饶钢《财报真相》三纵两横一张网体系，57+5 项检查点）做完整甄别；补充证据（审计意见、减持/质押、研发资本化、收现比、商誉、有息负债等）用 neodata-financial-search 查询 + WebSearch 交叉确认，取数可与 Step 2 其他数据**并行**抓取。

**输出形态：加粗小标题 + 3–4 段文字，不新增表格、不新增图片**（保持全文「4 表 12 图」结构不变，Step 7 断言不受影响）。固定四块内容，缺一不可：

1. **红黄绿灯结论**：🟢绿灯（无★异常且非★≤3）/ 🟡黄灯（★1–2 项或非★≥4 项）/ 🔴红灯（★≥3 或触发一票否决），并给一句定性（如「财务指标全绿，仅行为信号轻微异常」）
2. **★异常项清单**：逐条列★级异常，注明属行为信号（减持/质押/问询函）还是财务信号（现金流/资本化/一次性收益）；无异常则写「未发现★级异常」
3. **一票否决项核查**：证监会立案 / 存贷双高 / 净利与经营现金流长期背离——三项逐一给出核查结果（"未触发"也要写明）
4. **利润含金量提示**：OCF/归母现金含量、扣非/归母占比、收现比、应收周转天数、研发资本化率等关键证据数字（与矩阵数据同源同口径）；一次性收益占比高时明确提示估值锚应切换至扣非口径

> 小节文字必须与 fraud-detector 完整报告结论一致，数字标注来源与时点；正文其余章节引用甄别结论时以本小节为准。

### Step 3E · 绘制第八章④「估值通道图」（图11；2026-09-27 新增，2026-10-17 增加 PS/PB 分派）

**先定指标，再画图**：高成长科技公司用 **PS（市销率）**，传统公司用 **PB（市净率）**。判定按 `references/data-sources.md`「估值指标选择」的四步硬规则走，不得凭感觉：

1. **亏损 且 属科技成长类**（归母/扣非 ≤ 0 → PE 失效，但收入规模仍是有效定价锚）→ **PS 强制**
2. 行业属科技成长类（半导体/电子/计算机/通信/互联网/AI/创新药与器械/新能源储能/军工电子/新材料/高端装备）**且** 成长性达标（营收 TTM 同比 ≥20%、研发费用率 ≥5%、毛利率 ≥30%，满足 ≥2 项）→ **PS**

4. 用户显式指定 → 按用户

## 跨设备可用性（双通道）

用户会出差换电脑。本技能通过**三条通道并行**提供，内容必须保持一致：

| 通道 | 位置 | 触发 |
|---|---|---|
| **A · 独立技能** | `~/.workbuddy/skills/stock-research-report/` | 对话中自动加载 |
| **B · 专家** | `~/.workbuddy/plugins/marketplaces/my-experts/plugins/stock-analyst/skills/stock-research-report/` | 召唤「个股研报分析师」专家时加载 |
| **C · github 单仓** | `Desktop/WB/github-report-logic-audit/stock-research-report/`（与 report-logic-audit 同仓不同子目录） | 对外分发 |

**改动本技能后必须同步三边并刷新打包产物**。脚本固定在个人资产区（不随会话目录消失）：

```bash
PY="C:/Users/何亚轩/.workbuddy/binaries/python/envs/default/Scripts/python.exe"
"$PY" "C:/Users/何亚轩/.workbuddy/personal/scripts/sync_skill.py"           # 完整同步
"$PY" "C:/Users/何亚轩/.workbuddy/personal/scripts/sync_skill.py" --check   # 只读体检，不写文件
```

流程：同步副本 → 校验逐字节一致（A/B/C 三边）→ **元数据同代守卫** → **结构锚点守卫** → 打包技能包 → 校验并重注册专家 → 打包专家包 → 备份到 `~/.workbuddy/personal/skill-package/`。

> **结构锚点守卫**（v3 新增，2026-11-03）：校验 `build_report.py` 的章标题数=10、图占位符数=12、表编号对象恰为 1–4 且各定义一次，与 `chapter-spec.md` 声明同代。事故背景：chapter-spec 早定义四表，但 `build_report.py` 只给同业两表编号、仍标「表1/表2」，产出报告被测出 `FIG-GAP 表编号缺号` + 2 条 `FIG-REF-MISS`。
